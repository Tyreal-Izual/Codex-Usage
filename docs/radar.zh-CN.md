# Codex 降智雷达

[返回快速开始](../README.zh-CN.md)

Radar 默认启用，可通过工具栏复选框暂停或恢复采集。`codex_radar.py` 负责采集与缓存，
`static/radar.js` 和 `static/radar.css` 负责卡片展示。存在 Banked Resets 卡片时放在
它的下方，也支持只启用 Radar 来源。

## 当前数据源与展示

官网入口现位于 **模型智商 → 降智雷达**。这是首页标签切换，不是新的数据地址；
总分仍包含在首页初始 HTML 中，无需浏览器点击菜单或执行脚本即可采集。

本集成按 **2026-11-04** 核验的[官网首页降智雷达](https://codexradar.com/#stationmaster-round)
更新，评测分项为秦始皇、庞贝、鹈鹕、糖果。它与之前的 64 题 RadarBench 不同，
两套分数不混用，旧基准也不能作为新版回退数据。

- 直接读取官网总分表中已发布的 **总分 / 150**，不自行合成分项成绩，不执行页面
  脚本、不下载原作，也不读取账户数据。
- 当前核验目录包含 46 个配置：GPT-6.1 Sol、GPT-6 Astra、GPT-6.1 Terra、GPT-6 Sol、
  GPT-6 Luna、GPT-5.6 Sol、GPT-5.6 Terra、GPT-5.6 Luna。Luna 支持 low 至 max，
  其他模型包含 ultra。
- 卡片只展示分数和细条，条长为**分数 ÷ 150 × 100%**。按官网总分保留两位小数，
  所有模型共用固定满分 150。真实零分显示 `0.00` 和空条，缺失成绩显示 `—` 和虚线。
  不展示费用、耗时、历史曲线或旧 RadarBench 的覆盖题数、题次。
- 标题 age 表示距上次成功的**本地同步**经过多久。本轮测试时段单独显示：官网按
  北京时间发布起止时间，兼容分钟或秒精度，仪表盘转换为浏览器本地时区。同步成功不代表官网有新一轮测试。

## 刷新与失败处理

来源启用且服务运行时，每四小时只请求一次官网首页。已鉴权的 `GET /api/codex-radar`
只读内存缓存，浏览器刷新不会触发上游抓取，无需浏览器保持打开。休眠或离线会延迟同步。

每次请求的 socket 超时为 20 秒，响应上限为 4 MiB。超时、连接错误及 HTTP 502/503/504
最多**额外重试两次**，间隔 1 秒、3 秒。暂停或停止会唤醒等待，阻止下一次请求。
数据格式错误、证书错误及其他 HTTP 错误不立即重试。全部尝试失败后保留上次成功的
降智雷达快照和原同步时间，并按 15、30、60、120、最多 240 分钟定时退避；重启保留重试时间。

官网新增的判分进度说明与评分口径标题分开解析；按要求停测而没有总分的配置仍显示
`—`，不填成零分。只有全部 46 个配置、四分项/150 分说明、测试时段和分数范围通过校验才替换缓存。
页面不完整、模型目录变化或测试时段比现有快照更旧时，保留最后有效结果。官网 HTML
结构变化可能需要更新适配器。旧 IQ 和 RadarBench 缓存不再展示，升级后立即尝试获取新来源。

## 缓存与手动更新

默认缓存为每用户缓存目录下的 `codex_radar_snapshot.json`，可用 `CODEX_USAGE_CACHE_DIR`
覆盖目录。只保存规范化后的模型 ID、档位、总分和测试时段，不保存原网页或作品内容。

```sh
python3 codex_radar.py                 # 到期才更新，然后输出 JSON
python3 codex_radar.py --force         # 立即刷新磁盘缓存
python3 codex_radar.py --cache /tmp/radar.json
```

网页服务使用 `--cache-dir` 时，独立命令的 `--cache` 应指向同一目录中的
`codex_radar_snapshot.json` 文件。先停服务，再独立更新缓存，最后重启；独立命令不会
修改运行中服务的内存数据，也应避免两个进程同时写同一缓存。

```sh
python3 codex_radar.py --cache /tmp/codex-usage-cache/codex_radar_snapshot.json --force
python3 codex_claude_usage_web.py --cache-dir /tmp/codex-usage-cache
```

代码升级后需要重启网页服务，无需另设定时任务。分数来自社区评测，不代表账户用量或官方模型评分。
